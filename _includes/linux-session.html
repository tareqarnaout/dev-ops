Data streams, pipes & redirection

Every Linux command has three channels for data.

STDIN (0)
<-< /span>keyboard, file, or another command's output
STDOUT (1)
->terminal screen by default
STDERR (2)
->error messages, also screen by default
Operator Name Example
> Redirect - overwrite ls > files.txt
>> Redirect - append echo "done" >> log.txt
| Pipe to next command ps aux | grep nginx
2> Redirect errors only cmd 2> err.log
2>&1 Merge errors into stdout cmd > all.log 2>&1
< Read stdin from file mysql db < dump.sql
Most used in DevOps: journalctl -u nginx | grep ERROR | tail -50
2>&1 is essential when capturing all output in CI/CD pipelines.

Services with systemctl

systemd manages all background services on modern Linux. These are the commands you'll use daily.

sudo systemctl start nginx
start immediately
sudo systemctl stop nginx
stop running service
sudo systemctl restart nginx
stop + start
sudo systemctl reload nginx
reload config - no downtime
systemctl status nginx
check state + recent logs
Boot persistence
sudo systemctl enable nginx -> auto-start on reboot sudo systemctl disable nginx -> don't auto-start
Reading logs with journalctl
journalctl -u nginx
journalctl -u nginx -f  follow in real time
journalctl -u nginx --since "1 hour ago"
Deploy workflow: Edit config -> sudo nginx -t (test syntax) -> sudo systemctl reload nginx (zero downtime). If reload fails, journalctl -u nginx -n 50 shows why.
