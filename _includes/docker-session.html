What is Docker?

Docker packages your app and everything it needs into an isolated, portable unit called a container.

Problem it solves "Works on my machine" - Docker makes every environment identical: dev, staging, production.
vs Virtual Machine VMs virtualise the hardware (full OS per app). Containers share the host OS kernel - much lighter, starts in milliseconds.
Mental model: an image is a recipe. A container is a dish made from that recipe. You can make many containers from one image, and each runs independently.

Working with images

Click any command card to see a real terminal example.

Sample Dockerfile
FROM node:20-alpine # base image WORKDIR /app # working dir inside container COPY package*.json ./ # copy deps first (layer caching) RUN npm install # install inside image COPY . . # copy rest of source EXPOSE 3000 # document the port CMD ["node", "server.js"] # default start command
Layer caching tip: copy package.json and run npm install before copying your source code. Dependencies change less often - Docker caches that layer and rebuilds only what changed.

Networking & volumes

Containers are isolated by default - you must explicitly connect them.

Network drivers
bridge
Default. Container gets its own IP; use -p to expose ports to the host.
default
host
Container shares the host network stack directly. No port mapping needed - but no isolation either.
none
No networking at all. Fully isolated - useful for batch jobs that only read/write files.
custom
User-defined bridge. Containers on the same network can reach each other by container name (built-in DNS).
recommended
Volumes - persisting data
TypeWhat it isUse when
-v myvolume:/dataNamed volume - Docker manages storage locationDatabases, persistent state
-v $(pwd):/appBind mount - maps a host directory directlyLocal dev (live code reload)
--tmpfs /tmpIn-memory, not persisted to diskSensitive temp data
Key insight: containers are ephemeral - when they stop, their data is gone. Use docker volume create and mount it to keep data alive across restarts. Databases always need a volume.

Docker Compose

Define and run multi-container apps with a single YAML file.

version: '3.9' services: web: build: . # build from local Dockerfile ports: - "3000:3000" environment: - DATABASE_URL=postgres://db/myapp depends_on: - db # wait for db to start first db: image: postgres:16-alpine # pull from Docker Hub volumes: - pgdata:/var/lib/postgresql/data environment: - POSTGRES_PASSWORD=secret volumes: pgdata: # named volume, managed by Docker
Why Compose? Instead of running 4 separate docker run commands with all their flags, one docker compose up starts your entire stack. The file lives in version control - any developer can clone and run in one command.
